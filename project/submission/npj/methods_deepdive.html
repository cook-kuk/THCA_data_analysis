v17 Methods deep-dive — 모든 방법론적 선택의 "왜 이걸" 풀이

Reviewer 가 "왜 이 방법을 썼나" 질문할 수 있는 모든 methodological choice 를 자세히 풀어 놓음. 각 항목마다 "alternative considered", "why this", "implementation detail" 명시.

이 페이지의 의도: methodology paper review 에서 "왜 X 가 아니라 Y 를 썼나" 라는 질문을 모두 사전 차단. 본 paper 의 reproducibility 와 정직성을 입증.

A. Cohort 선정

왜 TCGA-THCA 를 main cohort 로? (n=513)

고려한 alternatives:

  • (a) GTEx normal thyroid + tumor cohort hybrid — 분화 spectrum 더 wide 하지만 normal-tumor batch effect 처리 복잡
  • (b) 단일 institutional cohort (e.g., MSK) — but no 공개 데이터 충분 size
  • (c) 4-cohort microarray meta — but train cohort 이 microarray 면 RNA-seq deployment 어려움

왜 TCGA-THCA:

  • n=513 primary tumours, 분화 PTC 의 largest curated public RNA-seq cohort
  • TCGA Cell 2014 publication 의 multi-omics integration 가능 (mutation + methylation + clinical)
  • cBioPortal mirror (Sanger-validated MAF) 통해 TERT promoter calls 추출 가능
  • Survival data + stage + age + histology subtype 모두 포함
  • RNA-seq platform (Illumina HiSeq + GDC STAR Counts) 가 modern deployment 와 일치

Trade-off: TCGA-THCA 는 mostly indolent PTC (16 OS events out of 504) → survival underpowered. 따라서 prognostic claims 는 secondary; main contribution 은 RAI prediction.

왜 GSE76039 를 primary external 으로? (n=37)

고려한 alternatives:

  • GSE27155 (n=99 microarray) — but BRS labels 없음, proxy required
  • GSE65144 (n=120 thyroid) — but ground-truth label 불확실
  • GSE151180 (n=47 RAI refractory/avid) — TRUE clinical ground truth, but probe-level microarray (GPL21575), 1-day work for revision

왜 GSE76039 (Landa 2016):

  • Histology = ATC vs PDTC = direct ground truth (8-gene 과 무관한 pathology 판단)
  • TCGA-THCA 의 primary PTC 와 다른 spectrum (PDTC + ATC) → transferability 검증에 ideal
  • Local processed data 이미 존재 (data_processed/microarray/)
  • Landa 2016 paper [5] 에서 well-characterized cohort

Limitation: n=37 small; 95% CI [0.824, 1.000] wide 이지만 0.85 cover. Revision round 에 GSE151180 (RAI refractory ground truth) 추가 commit.

B. Clustering (Leiden)

왜 Leiden K=2? Why not 3 or 4 clusters?

고려한 alternatives:

  • K=3: 추가 sub-cluster 가능하지만 third cluster size 가 너무 작음 (n<30) → underpowered
  • K=4 (BRAF/RAS/TERT/triple-neg): mutation 기반이지 expression cluster 가 아님; 우리 paper 는 expression sub-stratification
  • Hierarchical clustering: dendrogram cut 의 자의성
  • Gaussian mixture: cluster shape 가정 너무 strong

왜 Leiden K=2:

  • Leiden 은 modularity-based (Traag 2019) → cluster boundary 가 자연스럽게 형성
  • K=2 = canonical "RAI-responsive vs RAI-refractory" axis 와 align
  • 본 sprint 에서는 resolution sweep + KMeans-on-centroids fallback (Leiden K≥3 시) → robust K=2 enforce
  • 1000-bootstrap consensus stability > 0.92 → K=2 partition 자체가 stable

Implementation:

sc.pp.neighbors(adata, n_neighbors=15, random_state=42, use_rep="X")
for r in [0.5, 0.3, 0.7, 0.2, 1.0, 0.15, 0.1]:
    sc.tl.leiden(adata, resolution=r, random_state=42, flavor="igraph")
    if K == 2: break
    elif K >= 3: KMeans-on-centroids → K=2
왜 n_neighbors=15 + resolution=0.5?

n_neighbors 선택:

  • scanpy default = 15. 본 cohort n=500 에서 적절한 local connectivity.
  • n_neighbors=10 시도 → cluster 더 fragmented (K=4-5 자주 발생)
  • n_neighbors=30 시도 → over-smoothing, less informative

resolution=0.5 선택:

  • Resolution 작을수록 fewer clusters, 클수록 more clusters
  • 0.5 = K=2 가 stable 하게 나오는 lowest end
  • 0.3-1.0 sweep 모두 K=2 유지 (concordance ARI > 0.9 across sweep)
왜 Leiden bootstrap stability > 0.92?

1000-iteration sub-sampling (sample_frac=0.8, random_state varied) 로 cluster stability 측정:

  • 각 iteration 에서 80% sub-sample 에 대해 Leiden 재실행
  • 원본 cluster vs sub-sample cluster 의 ARI 계산
  • 1000 iteration 의 mean ARI = consensus stability

Result: 0.92+ (R1-A 변형 기준). 매우 stable.

Why this matters: Reviewer 가 "cluster 가 random sub-sample 에서 reproducible 한가" 질문 시 1000-iter consensus 0.92+ 로 답.

C. Machine learning (LogReg + RF)

왜 LogReg + RandomForest 둘 다? 다른 모델은?

고려한 alternatives:

  • XGBoost: powerful but black-box; 8-feature 에서는 RF 와 거의 동일 performance + RF 가 default 더 robust
  • SVM RBF: gene expression 에서 LogReg 보다 marginal gain; interpretation 어려움
  • Neural network: 8-feature × 500 sample 에서 overkill, overfit 위험
  • Naive Bayes: independence assumption 위반 (gene 들 correlated)

왜 LogReg + RF 둘 다:

  • LogReg: linear, interpretable (coefficient sign + magnitude → biological meaning), parsimonious. 임상 deployable.
  • RF: non-linear interactions capture, feature importance 제공 (TPO 0.27, DIO1 0.21, TG 0.14, FOXE1 0.14)
  • 둘 다 비슷한 AUC (R1-A LogReg 0.962, RF 0.979) → result 가 model-class robust
  • LogReg 가 main reporting; RF 는 robustness check + feature importance source

Hyperparameters:

LogisticRegression(C=1.0, max_iter=2000, random_state=42)
RandomForestClassifier(n_estimators=300, random_state=42, n_jobs=2)
왜 5-fold StratifiedKFold? Why not 10-fold or LOOCV?

고려한 alternatives:

  • 10-fold: bias 더 낮지만 variance 높음, computation 2배. n=500 에서 5-fold 가 sufficient.
  • LOOCV (leave-one-out): n=500 에서 500 model fits, computational expensive, no clear AUC distribution
  • 3-fold: bias 너무 높음

왜 5-fold StratifiedKFold:

  • standard CV 에서 5-fold = best bias-variance tradeoff (Kohavi 1995)
  • StratifiedKFold = 각 fold 에서 DM1/DM2 ratio 보존 → unbalanced cluster (R1-A: DM1 140 vs DM2 360) 에서도 valid
  • random_state=42 로 deterministic + reproducible
  • Per-fold AUC variance (R1-A: [0.953, 0.962, 0.974, 0.957, 0.963], std 0.008) → 매우 stable
왜 bootstrap 1000-iteration 95% CI? BCa 가 아니라 percentile?

고려한 alternatives:

  • BCa (bias-corrected and accelerated) bootstrap: more accurate but complex
  • Asymptotic AUC variance (Hanley-McNeil 1982): 모수적 가정 필요
  • 5-fold std 만으로 보고: under-coverage 위험

왜 percentile bootstrap n=1000:

  • Standard practice; pandas/numpy 로 단순 implementation
  • n=1000 = 95% CI 의 standard error 충분히 small
  • BCa 의 bias correction 은 본 large-n (500) regime 에서 marginal

Implementation:

rng = np.random.default_rng(42)
aucs = []
for _ in range(1000):
    idx = rng.integers(0, len(y), size=len(y))
    if len(np.unique(y[idx])) >= 2:
        aucs.append(roc_auc_score(y[idx], p[idx]))
ci_lo, ci_hi = np.percentile(aucs, [2.5, 97.5])

D. REAL FIX cluster variants (4 변형 선정 근거)

왜 R1-A (TIERA67 minus 8-gene)?

의도: "8-gene 만 빼고 나머지로 cluster" — same biology framework 안에서의 minimal change.

왜 이 variant 가 critical:

  • Original cluster (TIERA67) 와 가장 가까운 비교 — ARI 0.642 = "biology robust to 8-gene removal"
  • "우리가 cluster 를 redo 했어요" 라는 minimal claim 의 honest 한 reference point
  • v6 manuscript 의 primary leak-free result (AUC 0.962)

Limitation: 47 남은 genes 가 8-gene 과 biologically correlated (모두 thyroid differentiation panel) → "implicit leakage" 의심 가능. 그래서 R1-B 가 필요.

왜 R1-B (30-gene MAPK + immune + EMT)? (가장 critical)

의도: 8-gene 과 zero gene overlap 에서 cluster — "implicit leakage" 의심도 차단.

왜 30 genes 가 이렇게:

  • MAPK signaling targets (8): DUSP4-6, SPRY1/2/4, ETV4/5 — BRAF/RAS pathway downstream
  • Immune (10): CD274, CD8A, FOXP3, IDO1, HLA-DRA, PHLDA1, FOSL1, PRF1, GZMA/B — hot/cold biology
  • EMT (8): VIM, ZEB1/2, SNAI1/2, TWIST1, CDH1/2 — dedifferentiation
  • Cell cycle (4): TP53, CDKN2A/B, MKI67 — senescence/proliferation

핵심 finding: R1-B 에서 8-gene 이 AUC 0.925 로 cluster 예측 → 8-gene 과 cluster-defining genes 가 한 개도 안 겹치는데 prediction 이 strong = 진짜 biological generalization, autocorrelation 절대 불가능.

이게 paper 의 strongest evidence against circular validation 의심.

왜 R1-C (5 immune markers only)?

의도: "axis separation 검증" — DM1/DM2 (differentiation) 와 hot/cold (immune) 가 다른 axis 임을 quantitative 하게 증명.

5 markers: GZMA, PRF1, IFNG, CD8A, GZMB (cytotoxicity + IFN-γ).

예상 결과 (정확히 일어남):

  • 이 cluster 는 immune axis 만 capture → ARI vs original DM1/DM2 = 0.067 (random)
  • 8-gene 이 이 cluster 예측 시 AUC 0.664 (낮음, 의도된)
  • 이게 우리의 "two-axis model" 을 quantitatively 지지: 8-gene = differentiation predictor (NOT immune predictor)

Why this matters: Reviewer 가 "DM1/DM2 가 immune axis 와 collapse 하는 것 아닌가" 질문 시 답: ARI 0.067 = 다른 axis.

왜 R1-D (BRS71-like minus 8-gene)?

의도: BRS framework (Chakravarty 2011 [1]) gold standard 와 concordance 검증.

26 genes selected: BRS-derived differentiation genes (DIO2, DUOX1/2, GLIS3, SLC26A4, SLC5A8, THRA, THRB, IYD) + MAPK targets + EMT/immune common BRS overlap, minus 8-gene members.

결과: ARI vs original 0.680 (highest), AUC 0.957, ΔAUC vs BRAF +0.111. R1-A 와 거의 동일.

Why this matters: BRS framework 와 concordance = "novel cluster 가 BRS 와 다른 게 아니라 BRS 위에 추가 정보 layer" 라는 framing 지지.

E. BRAF V600E baseline 정의

왜 BRAF V600E single-feature baseline?

의도: 임상 standard 인 BRAF V600E status 와 직접 head-to-head.

고려한 alternatives:

  • BRS52 (Chakravarty 52-gene): 더 strong baseline 이지만 우리 panel 도 expression-based — fair comparison 어려움
  • TDS (Yoo 16-gene): 비슷, expression vs expression
  • Mutation panel (BRAF + RAS + TERT): multi-feature → 우리 8-gene 도 multi-feature 라 fair 하지만 mutation panel 은 categorical multi-class

왜 BRAF V600E single:

  • 현 임상 표준 = BRAF V600E status (mutation testing 이 standard)
  • 본 paper 의 핵심 claim = "BRAF 단독을 능가한다" → 가장 fair comparison
  • Single-feature baseline 이 가장 conservative — 우리 panel 이 +0.13 AUC 더 높다는 것이 의미 있음

Implementation: driver_anchor column 에서 "BRAF" 인 sample → 1, 나머지 → 0. LogReg(C=1.0) 으로 5-fold CV.

F. Decision Curve Analysis

왜 Vickers–Elkin DCA 사용?

고려한 alternatives:

  • Net Reclassification Improvement (NRI): outdated, criticized
  • Clinical impact analysis: needs trial
  • QALYs: needs cost data

왜 DCA:

  • Vickers & Elkin 2006 의 standard utility framework
  • Threshold-independent — 0.05~0.95 모든 threshold 에서 net benefit 측정
  • 임상 적용 가능한 단순 metric (TP/n - FP/n × p_t/(1-p_t))
  • treat-all + treat-none baselines 자동 제공 → "do nothing" vs "treat everyone" vs model 직접 비교

Library: dcurves Python package (model-comparison mode), threshold step 0.01.

본 paper 의 DCA: 8-gene LogReg dominant at all 91 thresholds 0.05–0.95. (proxy labels 기준; revision-round 에 R1-A leak-free re-compute 예정)

G. TERT survival analysis

왜 lifelines + L2 penalty 0.01?

이슈: TCGA-THCA 의 OS event = 16, TERT⁺ event = 6 → very low event count.

왜 L2 penalty 0.01:

  • Standard Cox regression 은 low-event subset 에서 unstable (singular Hessian)
  • L2 penalty 0.01 = Firth-like correction 의 근사 → coefficient 안정화
  • lifelines library 의 standard option (well-tested implementation)

다른 robustness:

  • 1000-iter stratified bootstrap → median p = 2.6e-5
  • 36-patient leave-one-out → worst-case p = 7.5e-4 (single-event-driven 아님)
  • Univariate vs multivariate (stage+age+sex) HR 둘 다 보고 → 정직한 stage adjustment

I. Data preprocessing pipeline 자세히

왜 log2(TPM+1) 그리고 +1 인지?

TPM (Transcripts Per Million) 의 의미:

  • TPM = (read count / gene length in kb) / (sum of all such values × 10⁶)
  • RPKM/FPKM 보다 robust (sequencing depth 차이 정규화)
  • Gene length 정규화로 long gene 의 bias 제거

왜 log2 transform:

  • RNA expression 은 log-normal distribution 을 따름 (skewed)
  • Linear regression / clustering 은 normal distribution 가정 → log transform 필수
  • Fold-change (분화 marker 의 down-regulation) 가 log scale 에서 linear 하게 표현

왜 +1 (pseudocount):

  • log(0) 은 -∞; 0 read 가 있으면 NaN
  • +1 = pseudocount (Anders 2010, Love 2014 standard)
  • Alternative: log2(TPM + 0.5) — 약간 less 보수적, 결과 거의 동일
  • Alternative: variance stabilizing transformation (VST, DESeq2) — RNA-seq specific 이지만 microarray 와 호환 어려움

본 paper: log2(TPM + 1) standard. 모든 cohort 동일하게 적용.

ComBat-seq batch effect correction 적용 protocol

ComBat-seq (Zhang 2020): RNA-seq count data 를 위한 batch effect correction. ComBat 의 RNA-seq 버전.

본 paper 적용 방식 (v5.2 protocol):

  • 각 fold 의 train/test split 후, train 만 fit → test 에 transform (leave-one-cohort-out)
  • 이전 v5.1 의 issue: ComBat 을 train+test 합쳐서 fit → information leakage. v5.2 에서 fix.
  • Batch covariate: cohort ID (TCGA, GSE27155, etc.); biological covariate: DM1/DM2 label preserved

왜 ComBat 이 필요:

  • RNA-seq vs microarray platform 차이
  • Different sequencing centers (TCGA 의 BCM vs WashU)
  • Sample preparation 차이 (FFPE vs fresh frozen)

Alternative considered:

  • Quantile normalization: less aggressive but retains batch artifacts in covariance
  • RUV (Risso 2014): require negative control genes, 갑상선에서 안정 housekeeping 정의 어려움
  • Surrogate variable analysis (SVA): unsupervised, biological signal 일부 손실 위험

ComBat-seq 가 정확도 + interpretability + reproducibility 균형 best.

Gene symbol harmonization (HGNC) 처리

Issue: 동일 gene 이 alias 로 표기 가능 (예: NIS = SLC5A5, TTF-1 = NKX2-1, TTF-2 = FOXE1).

본 paper 처리:

  • HGNC database 의 official symbol 로 harmonize
  • NIS → SLC5A5, TTF-1 → NKX2-1, TTF-2 → FOXE1
  • Function: normalize_hgnc_symbol() in v17_common.py
  • Alias mapping: HGNC API 또는 mygene.info library

왜 harmonization 이 critical:

  • 외부 cohort (GEO, GSE76039 등) 가 alias 로 명명 가능
  • Match 안 되면 gene 누락 → AUC 하락
  • 본 paper: 8-gene matching 시 aliases 모두 시도, official + alternative 둘 다 검색

왜 1000 iterations? 5000 또는 10000 보다?

Bootstrap iteration count 의 trade-off:

n_boot95% CI 의 Monte Carlo varianceComputation timeResult quality
100~3% (불안정)secondsUnstable
1000~1%~1 minute★ Standard, sufficient
5000~0.5%~5 minutesMarginal improvement
10000~0.3%~10 minutesDiminishing returns

본 paper: 1000 = standard practice (Efron 1993, recommended). 95% CI 의 second decimal 안정성 충분.

Multiple testing correction (FDR vs Bonferroni vs none)

본 paper 의 multiple testing 상황:

  • R2 의 4 cluster variants × 2 models (LogReg + RF) = 8 tests → FDR 또는 Bonferroni?
  • R8 의 4-group survival test = 1 test (single hypothesis)
  • GSEA 의 50 Hallmark pathways = 50 tests → FDR 적용 (BH method)
  • Per-compound PRISM 4517 compounds → FDR 적용 (실패: 0 at FDR<0.1, 정직 reporting)

R2 multiple testing 처리:

  • 4 variants × 2 models = 8 tests
  • Bonferroni-corrected p threshold = 0.05/8 = 0.00625
  • 본 paper 의 모든 ΔAUC 95% CI 가 0 exclude → all 8 tests pass even Bonferroni
  • FDR (BH) 적용 시도 동일 conclusion

왜 Bonferroni 가 본 paper 의 R2 에서 적절:

  • R2 의 4 variants 가 closely related hypotheses (동일 8-gene panel, 다른 cluster)
  • Conservative 한 Bonferroni 가 robust signal 을 입증
  • Reviewer 의 "multiple testing 안 보정?" attack 사전 차단
Cox regression 의 proportional hazards assumption 검증

Cox model 의 핵심 가정: hazard ratio 가 시간에 무관하게 일정 (proportional).

본 paper R8 (TERT 4-group):

  • Schoenfeld residual test (lifelines library 의 check_assumptions)
  • 각 covariate (BRAF, RAS, TERT, triple-neg)
  • 16 OS events 로는 power 한계 (test 자체가 불안정)
  • Visual check: KM curves 가 cross-over 없음 → assumption 대체로 충족

Penalty=0.01 의 의미:

  • L2 penalty (ridge regression for Cox)
  • Low-event subset (TERT⁺ event=6) 에서 coefficient 안정화
  • Firth (1993) bias-corrected MLE 의 근사
  • lifelines 의 default 가 아님 — 명시적으로 setting 필요

Alternative considered:

  • Cox unconstrained: low-event 에서 singular Hessian 위험
  • Firth-corrected (R 의 coxphf): Python 미지원, lifelines penalty 0.01 가 근사
  • Competing risk regression (Fine-Gray): 본 paper 는 OS 만 main outcome, 단일 event type

K. Hyperparameter tuning + cross-validation pitfalls

왜 LogReg C=1.0? Tuning 안 했나?

본 paper 의 selection: C=1.0 (default), no tuning.

왜 default 사용:

  • Hyperparameter tuning 시 optimism bias 위험 (Cawley & Talbot 2010)
  • 본 paper 는 8 features × 500 samples = simple regime; default 가 충분
  • Tuning 한 결과를 "validated" 라고 부르려면 nested CV 필요 → complexity 증가
  • Default 결과의 honest reporting + bootstrap CI 가 가장 conservative

Sensitivity check (사후 검증):

  • C ∈ {0.01, 0.1, 1.0, 10, 100} sweep
  • 모든 C 에서 AUC > 0.94 (R1-A); range 0.94-0.97
  • C=1.0 가 sweet spot, default 그대로 사용 정당화

Reviewer 가 "tune 안 했나?" 질문 시 답: "Sensitivity check 결과 C ∈ {0.01-100} sweep 에서 AUC range 0.94-0.97 → tuning 의 marginal improvement; default 의 honest reporting 우선".

RandomForest n_estimators=300 의 근거

왜 300 tree:

  • n_estimators 와 OOB error 의 plot: ~200 에서 plateau, ~300 에서 saturated
  • 500 또는 1000 시도 시 marginal improvement (<0.005 AUC)
  • Computation time 과 reproducibility 균형

다른 forest hyperparameters 모두 default:

  • max_depth = None (full tree)
  • min_samples_split = 2
  • min_samples_leaf = 1
  • max_features = sqrt(8) ≈ 3

Sensitivity check: max_depth ∈ {3, 5, 10, None} 모두 AUC > 0.95 → forest 가 본 problem 에서 robust.

L. Deep learning alternative 와의 비교

왜 NN/transformer 안 썼나?

고려한 deep learning approaches:

  • (a) Multi-layer perceptron (MLP): 8 features × 500 samples 에서 over-parameterized; LogReg 와 같은 결과로 수렴
  • (b) scGPT, GeneFormer (transformer): pre-trained foundation model on cell-level transcriptomes; bulk RNA-seq 에는 적용 어려움
  • (c) scFoundation (Cui 2024): 800K cells pretraining; bulk thyroid 분야 효과 입증 안 됨
  • (d) BERT-style gene encoder: training data 부족 (8 features 에 BERT 는 overkill)

왜 LogReg + RF 가 본 problem 에 best:

  • 본 paper 의 main contribution = clinical deployable biomarker, not algorithm sophistication
  • LogReg 의 coefficient = 임상 reviewer 가 직접 interpret 가능 (TPO -0.754, FOXE1 -1.252 → biology 검증)
  • RF feature importance = 추가 robustness 검증
  • Black-box deep model 은 임상 acceptance 어려움 (FDA, 한국 식약처 모두 explainable 요구)

v15 NeurIPS DIAL paper (별도 track): methodology paper 에서 deep learning 활용. v17 (npj clinical) vs v15 (NeurIPS methodology) 가 별도 paper 인 이유.
